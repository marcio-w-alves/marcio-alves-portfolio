# Test plan — Bilingual, whitelabel portfolio and review remediation (`i18n-whitelabel`)

Status: draft for approval · Inputs: `prd.md` (Rev. 2, POR-41…POR-70), `design.md` · Author: test strategist ·
Date: 2026-10-28

This plan says how we prove each acceptance criterion. It names every test after the behaviour it
proves, gives the real effect it asserts, and explains why it would fail without the change. The
implementer writes the tests to this plan. The test validator and the PR reviewer hold them to it.

**Default: the lowest level that gives real confidence.** E2E is a budget (§5). Anything provable
in RTL or in a node handler test is proven there.

### 1.2 Rules every test in this plan follows (owner's rules, made concrete)

1. **Test behaviour, not implementation.** UI tests query by role, label or text: `getByRole('link', { name: 'Português' })`, not by class or by `querySelector`. Server tests assert the HTTP status, the SSE events, the logged line and the persisted map size, not which helper ran.
2. **Mock only at the boundary.** The network goes through MSW (`setupServer`, `onUnhandledRequest: 'error'`, so a stray request fails the test). Time goes through `vi.useFakeTimers()` or an injected `now`. The language model is mocked at the HTTP layer (MSW on `api.openai.com`) in route tests, and at the `LanguageModelPort` in core tests: it is the out-of-process port, never the unit under test. `vi.mock` is allowed only for `next/navigation` (third party) and the AC-46.1 constant override (§3, POR-58).
3. **No fixed sleeps.** RTL uses `findBy*` and `waitFor`. Playwright uses web-first assertions, `expect.poll` and the existing `holdNextAnswer` gate. `waitForTimeout` is banned by test A-HYG (POR-62).
4. **E2E for critical journeys only** (§5), at most 8 new or behaviour-changed spec files.
5. **Every bug fix (POR-41, 42, 43, 57) has a regression test that fails on today's `main`.** The implementer proves it by committing the test first. The PR body shows the red run (test name and assertion message) before the fix and the green run after.
6. **No tautological or fabricated-state tests.** A test may not set the value it then reads back. It may not assert only `toHaveBeenCalled`. It may not seed a store into the state the flow is supposed to produce. Each negative case (wrong input rejected) sits next to its positive.
7. **Every scanner proves it can fail.** The whitelabel scan, the boundary rules, the client-reachability walk, the bundle scan, the hard-coded-copy check, the README check and the brand drift check each get a planted-violation self-test. A scanner that finds nothing on the real tree proves nothing until it has found something on a fixture.
8. **Names are behaviour sentences**, e.g. `keeps a factual sentence that starts like an offer`, not `isOffer works`.

### 1.3 Owner-agnostic tests (D33, FR-54, FR-55)

- Core, http, site and UI tests import `@/testing/fixture-profile` (§7.1). They assert the fixture's values ("Ada Rivera", "Acme").
- Tests that need the **real** profile assert only generic properties: the suggestion graph closes, the index hash matches, the translations are complete, every topic question gets a fast-path answer, the roles are sorted. They contain no literals.
- `src/profile/profile.test.ts` is the **only** test that names the owner. It holds the content assertions: D16, D17, D18, D19, D21, D22, the typos, and "Toptal is the current role".
- E2E reads expected visible text from `@/profile` through `e2e/support/profile.ts`. Answer _content_ is checked against profile data (knowledge fields and catalog questions), never by calling the fast path from the test. That would use the code under test as its own oracle.

## 4. Cross-cutting

### 4.1 Whitelabel and the fixture profile (FR-2, FR-54, FR-55, UC-4)

- **X-WL.1** `whitelabel.test.ts`: **real-tree scan.** Terms come from `profile`: full, first and last name; email; LinkedIn/GitHub URLs and handles; the site host; the phone (digits normalized, matched across separators); companies and aliases; product and school names. Matching is case-sensitive at word boundaries, minus `identity.nonIdentifyingTerms`. Scope: `git ls-files src scripts e2e public`, minus `src/profile/**`, `src/testing/fixture-profile/**` and binaries. Failure output: `file:line: "term" (kind)`.
- **X-WL.2** Self-test: plant a term in an in-memory file → it is reported with the exact line (T52.6).
- **X-WL.3** Non-vacuity: every term kind is non-empty for the real profile and for the fixture.
- **X-WL.4** Core literals: string and template literals in non-test `src/core/**` contain no metric value or knowledge year (AC-4.2). An AST walk with the TypeScript compiler API, not a regex, so `50%` in a comment or CSS is not a false positive.
- **X-WL.5** Core vocabulary: the words inside the profile's `vocabulary` rule sources, and the owner-specific intent names, appear nowhere in `src/core` (AC-4.3).
- **X-WL.6** Fixture overlap: fixture terms ∩ real-profile terms = ∅ (AC-54.1).
- **X-FX.1** `src/testing/**` is imported only by tests (rule `fixtures-only-in-tests`, fixture-proven).
- **X-FORK.1** `pnpm test:fork` = `PROFILE_UNDER_TEST=fixture vitest run`. `vitest.config.mts` aliases `@/profile` → `src/testing/fixture-profile` and excludes `src/profile/**/*.test.ts` (those belong to the profile a fork replaces). It must pass. This is the executable form of AC-54.2. It is added to the verify matrix in POR-63 and is required. The fixture therefore ships its own generated index (§7.1).
- **E2E**: `e2e/support/profile.ts` exports `copy(locale)`, `topicQuestions(locale)`, `answerArticleName(locale)` and `resumeUrl(locale)`, all read from `@/profile`. The specs import nothing else for expected text (X-WL.1 enforces it).
