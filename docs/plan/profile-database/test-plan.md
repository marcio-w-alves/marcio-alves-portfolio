# Test plan — Profile in a database, privacy cleanup of the repository (`profile-database`)

Status: draft for approval · Inputs: `prd.md` (Rev. 1, AC-1.1…AC-41.1, AC-NFR-8.1, deliverables D0–D9), `design.md`
(D4 split into D4a/D4b, §13 testing hooks) · Author: test strategist · Date: 2026-10-28

This plan says how we prove each acceptance criterion. It names every test after the behaviour it
proves, gives the real effect it asserts, and explains why it would fail without the change. The
implementer writes the tests to this plan. The test validator and the PR reviewer hold them to it.

**Default: the lowest level that gives real confidence.** E2E is a budget (§5). Everything the CLI does is
proven by driving the CLI, not by calling its internals; everything the store does is proven against a
real Postgres, never a mocked client.

### 1.2 Rules every test in this plan follows (owner's rules, made concrete)

1. **Test behaviour through the public surface.** Tooling tests run `pnpm profile <command>` (or the
   script) as a child process and assert its exit code, its output, the files it wrote and the rows in the
   database. Core tests call `compileLocaleCopy` and the chat handler, not private render helpers.
2. **Store tests never mock the database.** Each `*.store.test.ts` file creates its own database
   (`profile_test_<random>`) through the admin URL, runs the real `pnpm profile init` and drops it in
   `afterAll`. The `store` project **fails** (never skips) when `PROFILE_TEST_ADMIN_URL` is unset. No
   in-process fake of `pg`; the in-memory `ProfileWorkspace` is allowed only in U tests of use-case logic
   (diff grouping, digest), never as evidence for an AC that names the database.
3. **Mock only at the network boundary.** MSW with `onUnhandledRequest: 'error'`. Git is never mocked: the
   publish and history tests use real temporary repositories (`git init --bare` as `origin`).
4. **No fixed sleeps.** Waits are conditions: poll `pg_stat_activity` until the session under test is
   `wait_event_type = 'Lock'`; Playwright web-first assertions; fake timers for publish polling and retry
   backoff (injected `sleep`/`now`). Wall-clock is measured only where the AC is a time bound (AC-13.2).
5. **Every scanner and every check proves it can fail.** Each check of §4.2 of the design, the privacy
   scan, the dependency rule, the artifact scans and the equivalence oracle get a planted-fault twin. A
   check that passes on the real tree proves nothing on its own.
6. **No fabricated state.** A test may not insert the head pointer it then reads, may not hand-write
   `manifest.json` to test the next step (it runs `materialize`), and may not seed the result of the
   command it tests. Faults are planted in **inputs** (a bundle file, a SQL `profile.revise`, a lock held by
   another session), never in the code path.
7. **Credentials never leak through a test.** A shared `expectNoCredential(output, url)` helper asserts that
   stdout and stderr of every failing store/publish command contain neither the URL, the password, nor the
   token. It is called in every S and publish test that exercises an error path.
8. **Names are behaviour sentences**, e.g. `an interrupted import leaves the previous profile at head`.

### 1.3 Profile-agnostic tests (FR-25, D17)

- From D4a, CI materializes **only the example** (Ada Rivera). Tests read expected text from `@/profile`
  (the materialized profile), `e2e/support/profile.ts` or the example bundle — never a literal.
- The two owner-data tests that exist only during the migration (T1.2 bundle parity, T2.26 owner copy
  equivalence) contain **no owner literal**: they iterate the record's ids and compare two owner sources to
  each other. They are deleted in D8 with the TS owner modules.
- Privacy tests run on the example's terms and the example's `privacy.yaml` (fictional phone and phrases).
  The owner's terms appear only in owner-run M steps, and only as `kind` + `term#n` in anything recorded.

## 6. Evaluation (local only, NG10)

- **Model**: gpt-4o-mini for assistant **and** judge, set by env. No other model, ever. If the gpt-4o-mini judge
  fails calibration, the eval is skipped and recorded as skipped; it is not re-run with another judge.
- **Runs**: `--runs 1` only. Targeted with `--only <id>` wherever one case is the question (AC-17.1, T4a.17,
  T4b.5 use MSW, so CI never spends tokens).
- **Baseline (EV0.1)**: full run once on the pre-change `main`, saved case by case in `PROFILE_HOME/baseline/`.
- **Cutover (EV6.1, EV7.1)**: full `--runs 1` from the DB-materialized profile (D6) and against the cutover
  build (D7). A case that passed in the baseline and fails now gets **one** `--only <id> --runs 1` re-run; if it
  fails again it is a regression the owner decides on in writing. This replaces design §6's `--runs 3`
  majority (§9 A3).
